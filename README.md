## 项目解决的问题

日常健身常见的问题不是“没有动作”，而是计划、执行和复盘彼此割裂：训练计划难以坚持，重量、次数和身体反馈分散记录，饮水与恢复状态缺少统一视图，AI 建议又经常脱离真实数据。

本项目把以下流程放进同一个小程序：

1. 根据个人资料、目标、器械和可训练时间生成训练安排。
2. 记录每天的训练动作、组数、重量、次数、RPE、休息时间和完成状态。
3. 同步记录饮水、体重、身体围度与每日恢复状态。
4. 用统计图表、个人纪录、成就和训练周期展示长期变化。
5. 让 AI 教练通过工具读取真实数据，在受控范围内生成计划、分析表现和写入记录。

小程序采用欢迎页模式，不要求注册或登录；业务数据按微信 `openid` 隔离，存储在微信云开发数据库。

## 主要功能

| 模块 | 已实现能力 |
| --- | --- |
| 欢迎与协议 | 首次进入阅读并同意用户协议、隐私政策；支持小程序内原生协议页，不依赖外部域名 |
| 个人资料 | 昵称、性别、年龄、身高、体重、目标、训练经验、每周训练天数、单次时长和可用器械；实时计算 BMI |
| 智能训练推荐 | 根据目标、经验、器械和时长，从动作库筛选动作并生成 7 天训练计划；支持按日期固定当天推荐 |
| 训练计划 | 活跃训练周期优先，其次为自定义周计划，最后回退到规则推荐；支持一键生成、逐日编辑和休息日 |
| 训练执行 | 动作完成/取消完成、进度和完成率、训练计时器、组间休息倒计时、训练草稿自动保存与恢复 |
| 训练明细 | 每个动作记录多组重量、次数、RPE、是否力竭和休息秒数；支持动作备注与追加动作库动作 |
| 动作库 | 内置 44 个动作，覆盖胸部、背部、肩部、手臂、腿部、臀部、核心、有氧和拉伸；包含目标肌群、步骤、常见错误和提示 |
| 训练表现 | 动作历史、个人纪录（PR）、最近一次与上次表现对比、训练容量、趋势图和渐进负荷建议 |
| 训练周期 | 创建 4、6 或 8 周周期，按周渐进调整，自动安排减量周，生成每周总结和周期总结 |
| 饮水管理 | 每天杯数与单杯容量设置、一键喝一杯、手动添加、记录删除、历史与目标完成率 |
| 体重与围度 | 体重曲线；体脂率、腰围、胸围、臀围、手臂围和大腿围记录；同一天数据自动更新 |
| 身体状态 | 睡眠、疲劳、酸痛、训练意愿、整体状态五项评分及备注；支持历史修改和删除 |
| 今日建议 | 基于本地规则结合训练负荷、恢复和饮水状态生成建议，不依赖 AI 服务可用性 |
| 健身档案 | 训练、体重、身体、饮水和恢复统计，六类趋势图，11 项成就，以及 AI 数据分析入口 |
| 长期健身记忆 | 保存训练偏好、习惯、身体反馈、目标和 AI 备注；敏感信息过滤；每用户最多一条结构化记忆 |
| AI 健身教练 | 基于 DeepSeek OpenAI 兼容接口，通过 23 个工具读取、分析和写入当前用户数据；服务不可用时回退到本地规则回答 |
| 数据管理 | 训练、饮水、体重、围度、恢复和 AI 记忆的 JSON 导出；单类型 CSV 导出；JSON 导入、防重复和失败回滚 |

### AI 教练如何工作

AI 页面不会直接把所有数据一次性发给模型。云函数 `aiCoach` 使用 Agent 循环：

```text
用户问题
  -> 大模型选择工具
  -> 云函数按 openid 查询或写入云数据库
  -> 工具结果回填大模型
  -> 返回最终回答（最多 4 轮）
```

工具覆盖用户资料、今日训练、历史训练、饮水、动作库、动作历史、PR、训练容量、恢复状态、长期记忆、训练周期和综合报告。动作与数据均由工具返回，AI 不应凭空编造。

## 技术栈

- 原生微信小程序：JavaScript、WXML、WXSS
- 微信云开发：云数据库、云函数 `aiCoach`
- 云函数依赖：`wx-server-sdk`
- 大模型：DeepSeek `deepseek-chat`，使用 OpenAI 兼容的 Chat Completions 与 Function Calling 接口
- 图表：微信小程序 Canvas 2D
- 本地能力：`wx.setStorageSync` 缓存与训练草稿

## 安装方法

### 1. 环境准备

- 安装[微信开发者工具](https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html)。
- 准备一个可使用云开发的微信小程序 AppID。
- 如需运行静态检查，准备 PowerShell 7（`pwsh`）。

克隆项目：

```bash
git clone <your-repository-url>
cd Sport
```

### 2. 导入小程序

1. 在微信开发者工具中选择“导入项目”。
2. 项目目录选择本仓库根目录；`project.config.json` 已将 `miniprogram/` 配置为小程序源码目录。
3. 填写自己的 AppID。仓库中的 `project.config.json` 带有现有 AppID；如果你没有该小程序的管理权限，请替换为自己的 AppID。
4. 确认项目类型为“小程序”，不是小游戏或公众号网页。

### 3. 开通云开发

1. 在微信开发者工具顶部打开“云开发”并创建环境。
2. 当前代码通过 `wx.cloud.init({ traceUser: true })` 使用默认云环境。
3. 如果账号下存在多个环境，需要在 `miniprogram/app.js` 的 `wx.cloud.init` 配置中显式填写目标环境的 `env`。

### 4. 创建云数据库集合

在云开发控制台创建以下 14 个集合：

| 集合 | 用途 | 建议权限 |
| --- | --- | --- |
| `users` | 用户资料 | 仅创建者可读写 |
| `exercises` | 公共动作库 | 所有用户可读，仅创建者可读写 |
| `week_plan` | 自定义 7 天计划 | 仅创建者可读写 |
| `workout_records` | 动作训练记录 | 仅创建者可读写 |
| `workout_sessions` | 训练会话与总时长 | 仅创建者可读写 |
| `water_settings` | 每日饮水目标 | 仅创建者可读写 |
| `water_records` | 饮水记录 | 仅创建者可读写 |
| `weight_records` | 体重记录 | 仅创建者可读写 |
| `body_measurements` | 体脂率与身体围度 | 仅创建者可读写 |
| `recovery_records` | 每日恢复状态 | 仅创建者可读写 |
| `fitness_memory` | 长期健身记忆 | 仅创建者可读写 |
| `training_cycles` | 训练周期 | 仅创建者可读写 |
| `training_cycle_weeks` | 周期周总结 | 仅创建者可读写 |
| `achievements` | 成就解锁记录 | 仅创建者可读写 |

首次启动时，`miniprogram/app.js` 会检查 `exercises` 集合；如果集合为空，会自动写入 `miniprogram/data/exercises.js` 中的 44 个动作。该初始化是幂等的，已有动作时不会重复导入。

### 5. 部署 AI 云函数

如果不配置 AI，训练、饮水、身体数据和本地建议仍可使用，但 AI 教练只会走本地兜底逻辑。

1. 在开发者工具中右键 `cloudfunctions/aiCoach`。
2. 选择“上传并部署：云端安装依赖”。
3. 在云开发控制台将 `aiCoach` 超时时间设置为 60 秒。
4. 为云函数添加环境变量 `AI_API_KEY`，值为你的 DeepSeek API Key。
5. 如需更换模型服务，修改 `cloudfunctions/aiCoach/config.js` 中的 `BASE_URL` 和 `MODEL`。

API Key 只允许放在云函数环境变量中。不要写入 `miniprogram/config.js`、`miniprogram/app.js` 或任何会提交到 Git 的文件。

### 6. 编译运行

在微信开发者工具中点击“编译”，使用模拟器或真机调试进入小程序。首次使用时：

1. 阅读并勾选协议。
2. 进入“我的” -> “我的资料”完成个人资料。
3. 返回首页或训练页查看推荐计划。

### 可选：部署协议 H5

小程序内协议不依赖 H5。`docs/legal/terms.html` 和 `privacy.html` 是独立的静态页面，可部署到任意 HTTPS 静态托管，供浏览器访问。具体说明见 [`docs/legal/README.md`](docs/legal/README.md)。

## 使用方法

### 首次使用

1. 在欢迎页勾选《用户协议》和《隐私政策》。
2. 填写目标、经验、训练频率、单次时长和器械。
3. 系统根据资料生成 7 天计划，并优先展示今天的训练。

### 日常训练

1. 在“训练”页查看今日动作、本周计划和完成进度。
2. 可点击“智能推荐”重新生成周计划，也可进入“编辑计划”逐日选择动作或设为休息。
3. 点击“开始训练”进入明细页，开始计时并按组填写重量、次数、RPE 和休息时间。
4. 完成动作后可标记完成；训练草稿会在本地和云端自动保存。
5. 点击动作可查看该动作的历史、PR、容量和趋势。

训练计划的实际优先级为：

```text
活跃训练周期 > 自定义周计划 > 规则推荐
```

### 记录饮水与身体状态

- 饮水页支持设置每日杯数和单杯容量、快速“喝一杯”、手动追加与删除记录。
- “我的” -> “体重”记录体重并查看近 30 天曲线。
- “健身档案” -> “身体围度”记录体脂率及五项围度。
- “首页” -> “今日状态”记录睡眠、疲劳、酸痛、训练意愿和整体状态。

### 查看统计与长期趋势

“我的” -> “健身档案”会汇总训练、体重、身体、饮水和恢复数据，展示：

- 训练次数、完成率、容量、平均时长和 PR
- 体重变化与身体数据
- 饮水达标情况
- 恢复状态
- 六类趋势图
- 成就解锁进度
- AI 数据分析结果

### 使用 AI 教练

可从 AI 悬浮球或 AI 页面进入，直接使用自然语言提问：

- “今天应该练什么？”
- “我今天只有 20 分钟，也没有器械，帮我重新安排。”
- “我上次卧推用了多重？”
- “帮我记录今天卧推 3 组，每组 60kg 做 8 次。”
- “分析一下我最近的训练、体重、恢复和饮水情况。”

AI 不可用或未配置 Key 时，页面会用本地规则展示今日训练或饮水统计，并明确提示处于兜底模式。

### 导出与恢复数据

进入“健身档案” -> “数据管理”：

- 选择“全部数据”或单个数据类型导出 JSON。
- 仅导出单一类型时可选择 CSV。
- 导入时粘贴本应用导出的 JSON。系统会校验格式、跳过重复记录，并在整体异常时回滚本次写入。

## 输入输出示例

### 1. 个人资料 -> 训练计划

示例输入：

| 字段 | 输入 |
| --- | --- |
| 目标 | 增肌 |
| 经验 | 初级 |
| 每周训练 | 3 天 |
| 单次时长 | 45 分钟 |
| 可用器械 | 哑铃 |

示例输出：

```text
今日训练：胸部 + 三头
1. 哑铃卧推  4 组 × 10 次  休息 60 秒
2. ...
```

具体动作和组数由动作库、资料、日期和规则筛选共同决定，以上仅展示输出形式。

### 2. 训练组输入 -> 存储结果

用户在训练明细页输入的每一组：

```text
重量：20 kg
次数：10
RPE：8
力竭：否
休息：90 秒
```

保存后会进入 `workout_records.set_records`：

```json
{
  "weight": 20,
  "reps": 10,
  "rpe": 8,
  "is_failure": false,
  "rest_seconds": 90
}
```

训练容量按各组 `重量 × 次数` 求和，用于趋势、统计和 AI 分析。

### 3. AI 对话

示例输入：

```text
我今天只有 20 分钟，也没有器械，帮我安排一次训练。
```

示例输出形式：

```text
今天安排 4 个自重动作，预计 20 分钟：
1. 俯卧撑 3 组 × 12 次
2. ...

动作全部来自动作库；实际组数和动作会结合你的资料、
今日计划、训练历史和恢复状态调整。
```

模型回复的自然语言不固定，但训练动作、记录和统计应来自云函数工具读取的真实数据。

### 4. 数据导出

单类型体重数据的 JSON 导出示意：

```json
{
  "app": "健身小助手欣一",
  "format": "fitness-xinyi-export",
  "version": 1,
  "exported_at": "2026-10-22 18:30",
  "types": ["weight_records"],
  "data": {
    "weight_records": [
      {
        "date": "2026-10-22",
        "weight_kg": 72.4
      }
    ]
  }
}
```

导入同一文件时，输出为“新增 / 跳过重复 / 失败”的数量统计。已存在的记录不会覆盖。

## 数据与安全

- 所有业务数据按微信 `openid` 隔离；云函数侧也只使用当前调用者的 `OPENID` 查询和写入。
- AI API Key 只从云函数环境变量 `AI_API_KEY` 读取，不进入小程序前端。
- AI 输入限制 500 字，对话历史最多 10 条，Agent 最多 4 轮；工具结果过长时会截断并提示模型。
- 长期健身记忆会过滤手机号、身份证号、银行卡号、邮箱等敏感信息。
- 小程序不调用手机号、头像、位置、相册、麦克风或摄像头等微信隐私接口。
- 训练建议、BMI、恢复建议和 AI 回答仅供参考，不构成医疗诊断。出现疼痛、伤病或身体不适时应停止相关训练并咨询专业人士。

## 静态检查

项目目前没有自动化测试框架，提供静态结构检查脚本：

```powershell
pwsh -NoProfile -File ./scripts/check-project.ps1
```

脚本会检查 JSON 可解析、WXSS 花括号、WXML 标签配对、页面四件套、TabBar 图标和全局组件资源引用。

## 已知边界

- AI 需要部署 `aiCoach` 云函数并配置有效 API Key；未配置时只能使用本地规则兜底。
- 当前未实现账号注册、登录、多端账号绑定或服务端推送。
- 小程序端统计和个人数据查询按 MVP 规模设置了分页上限；数据量显著增长后，应改为云函数聚合或服务端分页。
- 数据导入只接受本项目导出的 JSON 格式，不直接接受普通 CSV。
- 本项目采用 [MIT License](LICENSE)；公开分发或商用前仍建议完成隐私、协议和第三方服务的合规审查。
